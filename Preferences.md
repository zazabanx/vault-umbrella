# Preferences

How the user works, and what needs a yes. Product status does not go here. Add a line only after the user has used the rule on a real product.

## Who does what

- Grok Bot orchestrates. Claude advises and reviews. Coding agents work in the private GitHub repo. Notifications go to the Grok Bot chat. (AutoClip, 2026-10-08)
- The user has the final say on what matters to them.
- A plan that Grok Bot and Claude have both reviewed and agreed can go ahead without waiting. (2026-10-13)
- Only a major or make-or-break Claude prompt needs the user's approval. (2026-10-08)
- Tell the user only about major issues. Claude still sees every error. (2026-10-14)
- When work is promised as next, start it in that same turn. If it has to wait, put a time on it. (2026-10-15)

## Models and tools

- Pick the model per task. Do not drop to a weaker model when the work needs a stronger one. Ask before a choice that might overrun plan limits. (2026-10-08)
- AutoClip's default reviewer is Opus. That stays in the AutoClip vault. Do not copy it here as a rule for every product.
- The next small product uses Claude Code. AutoClip stays on Cursor. Do not start that switch from a template. (2026-10-14, recorded 2026-10-16)

## Memory

- Memories for a product live in that product's vault. Shared rules live in this repo. Do not write Claude's default memory files for these projects.
- Create a note only when no existing note fits. Append otherwise.
- No secrets in any vault.
- Commit by hand. Do not turn on an auto-commit plugin.
- Compare the build-loop stamp by hand when the loop changes ([[build-or-improve]]). It is not a scheduled job.

## Routines

A daily note and a weekly look-back stay off until the user turns them on for that product. AutoClip's clock is 11:30 PM ET, and Sunday dreaming is off. Do not copy that clock into a new product as if it were on.
